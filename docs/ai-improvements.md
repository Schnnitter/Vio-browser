# Vio: улучшения ИИ и безопасности

## 1. Open URL — валидация домена
- Файл: scripts/ai.js, функция typeAndGo (примерно строки 1311-1337).
- Проблема: `typeAndGo()` принимает любой URL из модели через тег `<открыть>…</открыть>` и вызывает `App.navigate()` без проверки домена, блок-листа и allowlist для безопасных доменов.
- Решение: добавить `sanitizeNavigationTarget(url)` перед `App.navigate()`: `new URL()`, запрет `localhost`, IP, частных сетей, `xn--` и локального denylist; для открытий только из результатов поиска применять allowlist `github.com`, `wikipedia.org`, `*.wikipedia.org`, `*.github.com`, `*.example.com` и т.д., а иначе `App.search()` или отказ.
- Бесплатно, без ключей: вся проверка выполняется в браузере локально, без внешних сервисов и без новых зависимостей; это минимальный JavaScript-код и не меняет UX для обычных безопасных ссылок.

## 2. Vision — мелкие элементы (капчи)
- Файл: scripts/ai-agent.js, функции visionProviders / recognizeImage / ocrPrepared (примерно строки 2314-2379).
- Проблема: скриншот 1280px JPEG 0.82 слишком груб для мелких капч в углу экрана; после сжатия 5×20 пикселей почти исчезают, и OCR/vision не видят символы.
- Решение: перед отправкой в vision/ocr анализировать кадр по `ImageData` и находить зоны с низкой площадью, качеством, контрастом и мелким текстом; для каждой зоны делать `crop + 2x/3x upscale + sharpen`, а затем уже `visionAsk()`/`ocrPrepared()`; помечать только эти зоны, а не весь скрин.
- Бесплатно, без ключей: локальный canvas + `drawImage()` + `getImageData()` не требуют API и работают без новых библиотек; можно сделать как один дополнительный preprocessor на клиенте.

## 3. Поиск — новые бесключевые эндпоинты
- Файл: scripts/ai-agent.js, функции toolSearch / toolWiki / toolGithub / toolWeather / toolTranslate (примерно строки 520-800).
- Проблема: DuckDuckGo HTML и lite-портал ломаются капчей или пустым HTML; fallback на instant answer даёт только короткие факты и не возвращает ссылки, поэтому качество поиска нестабильно.
- Решение: добавить второй и третий источник в цепочку: `https://search.brave.com/search?q=...` (без ключа, но не гарантированно всегда доступен), `https://www.mojeek.com/search?q=...` и `https://www.marginalia-search.com/search?query=...` как fallback; нормализовать ответы в общий формат `[{title,url,summary}]` и если ответ пустой — возвращать `null` без падения.
- Бесплатно, без ключей: эти провайдеры реально работают без регистрации и не требуют платной подписки; это безопаснее, чем тянуть “одноразовые” host-specific решения, и не требует централизованного сервера.

## 4. LLM — расширить бесключевую цепочку без платных API
- Файл: scripts/ai-agent.js, функции builtinProviders() и providers() (примерно строки 58-119).
- Проблема: Pollinations → LLM7 → Legacy находятся в одной сети через общий IP и все имеют схожий rate limit; при 429 у одного падает вся цепочка, hedge помогает только когда оба живы одновременно.
- Решение: добавить в список fallback только те публичные OpenAI-совместимые endpoints, которые проходят локальный live-probe без Authorization, без обязательной регистрации и без платного аккаунта; в текущем списке допустимы только уже проверенные `text.pollinations.ai` и `api.llm7.io`, а все остальные кандидаты добавляются только после `curl -I`/POST-probe и проверки статуса `200` без ключа; если endpoint требует ключ, он в `providers()` не попадает.
- Бесплатно, без ключей: нужно держать только провайдеры, которые реально анонимно принимают запрос без ключа и без входа; если endpoint требует ключ, логин или платный аккаунт — он не подходит для “works out of the box”.

## 5. Stream — поддержка `tool_calls` в SSE
- Файл: scripts/ai-agent.js, функции streamBridge() / httpStream() / payload() (примерно строки 131-280).
- Проблема: текущий парсер читает только `choices[0].delta.content` и игнорирует `delta.tool_calls`; если провайдер начнёт отдавать команды как tool_calls, они будут потеряны и VioScript не получит `КЛИК`, `ВВЕСТИ`, `ПОИСК`.
- Решение: в `payload()` и `httpStream()` добавлять ветку `if (d?.choices?.[0]?.delta?.tool_calls)` и собирать список `tool_calls` в `accToolCalls`; затем в конце ответа конвертировать `tool_calls` в существующий формат VioScript через `normalizeToolCalls()`, а не падать на `content`; приоритет: сначала `content`, если пустой — `tool_calls`.
- Бесплатно, без ключей: это расширение только для формата SSE и не требует новых платных движков; оно улучшает совместимость с несколькими OpenAI-совместимыми провайдерами без перемены модели по умолчанию.

## 6. OCR — надёжная загрузка без единой точки отказа
- Файл: scripts/ocr.js, функции ensureLib() / read() / readFull() (примерно строки 1-92).
- Проблема: Tesseract грузится с `cdn.jsdelivr.net`; если CDN недоступен или первый запрос падает, OCR не работает совсем, а пользователь получает молчание без fallback.
- Решение: реализовать `ensureLib()` с кешем в `localStorage['vio.ocr.cache']`, двумя CDN (`jsdelivr`, `unpkg`), локальным `try/catch`, таймаутом и повтором; при первом успехе сохранять `src` в кэше; если загрузка с одним CDN не удалась — пробовать второй без пользовательского участия.
- Бесплатно, без ключей: Tesseract и CDN — свободные ресурсы; это не меняет бизнес-модель и не требует регистрации, зато убирает зависимость от одного хоста.

## 7. Язык ответов — жёсткая инструкция и few-shot
- Файл: scripts/region.js, функции `answerLine()` и `promptLine()` (примерно строки 187-204); также scripts/ai.js, часть с `Region.answerLine()` (примерно строки 405-409).
- Проблема: `answerLine()` задаёт язык, но бесплатные провайдеры часто игнорируют и отвечают на английском/русском, особенно в регионах вроде Казахстана, где они “схлопывают” языковую модель в общий шаблон.
- Решение: усилить промпт с явным `response_language` + `few-shot` примерами: `Пиши на языке «kk»`, `Примеры: ...` + `Если пользователь пишет по-русски/казахски — отвечай на его языке` в `system` и `user` сообщении; в `Region.answerLine()` добавить режим `strictLanguage` и повторять язык в конце ответа.
- Бесплатно, без ключей: это локальная инструкция модели, без платных API и контрактов; чуть больше токенов, но рано/поздно это дешевле, чем “ответ на неверном языке”.

## 8. Дорогие запросы — лимит ресурсов за один прогон
- Файл: scripts/ai-agent.js, функции httpStream(), toolSearch() / toolWiki() / toolGithub() и планировщик чата (примерно строки 325-380 и 700-800).
- Проблема: один пользовательский запрос может инициировать десятки внешних сетевых вызовов (`поиск + wiki + github + weather + translate + скан страницы`), что превышает лимиты провайдеров и ухудшает UX в плохой сети.
- Решение: добавить на один прогон `requestBudget`: `maxExternalCalls=3`, `maxResults=5`, `maxChars=12000`, `maxToolDepth=2`; обрубать цепочку `toolSearch → wiki → github`, если уже использовано 3 внешних вызова, а после этого возвращать “нужно сузить запрос” без дополнительного сетевого IO.
- Бесплатно, без ключей: это ограничение внутри браузера, не требует платных сервисов и защищает от внешних блокировок и rate limit; при этом сохраняется “работает из коробки без настройки”.
